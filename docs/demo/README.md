# DEF CON Demo Pack

Two scripts drive the whole talk. Standalone `cap*.sh` scripts remain as fallbacks.

## The 2-script flow

```bash
# 1. ONCE before the talk (builds binary + images, starts containers, pre-profiles)
./docs/demo/setup.sh

# 2. ON STAGE — press Enter between chapters
./docs/demo/run-demo.sh

# optional:
./docs/demo/run-demo.sh --from 7      # jump to RCE chapter
./docs/demo/run-demo.sh --record      # asciinema per chapter → docs/demo/recordings/
./docs/demo/run-demo.sh --list        # list chapters
```

`setup.sh` writes `docs/demo/.demo-env` (container IDs, ports, profile paths).
`run-demo.sh` sources it, primes sudo once, and walks 8 chapters.

### Reset / restart the pipeline

```bash
./docs/demo/cleanup.sh            # stop enforcement, remove containers + generated state
./docs/demo/cleanup.sh --all      # also remove built images and recordings
./docs/demo/setup.sh              # rebuild from scratch
```

`cleanup.sh` keeps recordings and images by default (so a re-`setup.sh` is fast); use `--recordings` / `--images` / `--all` to remove them, `--keep-events` to preserve profiled JSON.

## Containers (kept up with `--restart unless-stopped`)

| Name | Image | Port | Role |
|------|-------|------|------|
| `ebpf-mon-workload` | `docs/demo/workload/` | — | Rich event generator for C1 monitoring |
| `vulnapp` | `docs/demo/cve/` | 8080 | RCE target for C7 containment |
| `secretsvc` | `docs/demo/secretsvc/` | 8081 | Data-exfil target for C8 |

Containers are never torn down by the orchestrator. If one dies, `setup.sh` (or `docker start <name>`) brings it back.

**Security — ports bind to loopback only.** `vulnapp` is an unauthenticated RCE and `secretsvc` leaks a secret, so `setup.sh` publishes them as `127.0.0.1:8080` / `127.0.0.1:8081` — **not reachable from the WiFi/LAN**. The demo only ever curls `127.0.0.1`. Only override with `BIND_ADDR=0.0.0.0 ./docs/demo/setup.sh` on an isolated, trusted host. Verify with `ss -ltnp | grep -E ':8080|:8081'` (should show `127.0.0.1`, never `0.0.0.0`/`[::]`).

## Enforcement logging note

`run-ebpf.sh` and the orchestrator use `sudo env RUST_LOG=info` (not `sudo -E`) so `ENFORCEMENT DENY` / `AUDIT` lines survive sudoers policies that ignore `-E`. If you run the binary by hand:

```bash
sudo env RUST_LOG=info target/release/ebpf-mon --name vulnapp \
  --enforce docs/demo/vulnapp-events.json
```

## Troubleshooting

**Container exits when you Ctrl+C the monitor** — that only happens if you somehow linked them; setup uses `--restart unless-stopped`, so `docker start <name>` (or re-run setup) brings it back. The orchestrator never stops the containers.

**`BPF-LSM is not supported`** — `bpf` must appear in `/sys/kernel/security/lsm`. Add it to the `lsm=` boot param and reboot (see talk notes).

**Profile missing (`vulnapp-events.json`)** — re-run `./docs/demo/setup.sh` without `--skip-profile`. Profiling needs root + ~20s of warmup traffic.

**Profile is EMPTY (`net=0 fs=0 proc=0`)** — `setup.sh` warns loudly when a learned profile has no events. An empty allow-list will block the app itself under enforcement. The usual cause is that the app was **idle** during the warmup window, so make sure the warmup drives real, distinct traffic for the whole window and confirm the counts printed by `setup.sh` are non-zero before the talk. (Historical note: a startup-ordering bug used to drop every event fired before the userspace perf-buffer readers were open — worst for short bursts on otherwise-idle apps. That is fixed: readers are now opened before the probes are attached.)

**HTTP 503 under enforcement** — the profile missed a dependency (often DNS). Re-profile with the warmup loops, or diagnose with `--audit-only` and read the deny lines.

## Note on `profiled_inode` (removed)

Earlier revisions of the IR carried an optional `profiled_inode` per file/process
rule. It was **removed** because nothing in the enforcement path ever used it
(the loader never read it; the kernel matches files by path-hash, not inode),
inodes are volatile across runs so they can't be a durable policy key anyway, and
carrying a per-file inode actively defeated deduplication. Dropping it gives a clean,
target-neutral IR. Monitoring still captures inodes on the raw event path.
